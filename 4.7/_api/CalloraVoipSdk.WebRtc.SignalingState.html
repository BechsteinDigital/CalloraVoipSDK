Enum SignalingState

Namespace
CalloraVoipSdk.WebRtc
Assembly
CalloraVoipSdk.Client.dll

The RFC 8829 §4.1.3 signalling state of a WebRTC IPeerConnection — the offer/answer half of the peer's lifecycle, distinct from the ICE/DTLS transport lifecycle exposed by PeerConnectionState. It mirrors the W3C RTCSignalingState, tracking where the peer sits in the SDP negotiation: whether an offer is pending locally, pending from the remote, or the exchange has settled.

This SDK negotiates a single offer/answer exchange per peer (re-offer / renegotiation is a later package), so the state moves Stable → HaveLocalOffer → Stable (offerer) or Stable → HaveRemoteOffer → Stable (answerer) and then to Closed. The provisional-answer state (have-local-pranswer / have-remote-pranswer) is not used by this SDK — no a=pranswer path exists — and is therefore not modelled. 

public enum SignalingState

Fields

Closed = 3

The peer has been closed; no further negotiation is possible (RFC 8829 §4.1.3 closed).

HaveLocalOffer = 1

A local offer has been produced (CreateOffer()) and applied, and the peer is waiting for the remote answer (RFC 8829 §4.1.3 have-local-offer — the offerer role).

HaveRemoteOffer = 2

A remote offer has been applied and the peer is producing the local answer (RFC 8829 §4.1.3 have-remote-offer — the answerer role). Transient: the answerer moves through this state and back to Stable within a single SetRemoteDescriptionAsync(string, CancellationToken).

Stable = 0

No offer/answer exchange is in progress: either none has started, or the last one completed. This is the initial state and the resting state between negotiations (RFC 8829 §4.1.3 stable).
