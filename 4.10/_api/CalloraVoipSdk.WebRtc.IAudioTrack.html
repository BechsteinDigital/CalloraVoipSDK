Interface IAudioTrack

Namespace
CalloraVoipSdk.WebRtc

A handle to an outbound audio track added with AddAudioTrack() (its own m=audio line on the shared BUNDLE transport, beyond the peer's primary audio anchor). Send encoded audio payloads on this track with SendFrameAsync(ReadOnlyMemory<byte>, uint, CancellationToken); each track carries its own SSRC, so payloads sent on distinct handles never collide (RFC 3550 §8.1). The SFU pattern of one audio stream per remote participant on a single peer connection.

public interface IAudioTrack

Remarks

Adding a track supplements the peer's implicit primary audio track (the always-on transport anchor that SendAudioAsync(ReadOnlyMemory<byte>, CancellationToken) addresses); the frameless SendAudioAsync(ReadOnlyMemory<byte>, CancellationToken) keeps addressing that primary track. A track added before CreateOffer() is negotiated in the first offer; a track added mid-call is pending until the next offer/answer cycle applies it to the live session (RFC 8829 renegotiation). Audio has no simulcast, so there is no per-layer send overload. DTMF (RFC 4733) stays on the primary audio track and is not surfaced per additional track — send it via SendDtmfAsync(byte, int, CancellationToken).

Methods

SendFrameAsync(ReadOnlyMemory<byte>, uint, CancellationToken)

Sends one already-encoded audio RTP payload on this track, with rtpTimestamp set on the outbound RTP packets (RFC 3550 §5.1). The app owns the codec (transport-only). The timestamp is stamped on the wire — not derived from an internal cursor — so an SFU forwarding this stream preserves the source's timestamp for A/V-sync against forwarded video; the app supplies the source's own RTP timestamp per payload. Suppressed until the DTLS handshake keys the transport; a no-op when the negotiated directions do not carry outbound audio on this track (a send-only/inactive remote answer, or a recv-only/inactive local side, RFC 3264).
