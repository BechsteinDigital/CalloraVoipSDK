Interface IPeerConnection

Namespace
CalloraVoipSdk.WebRtc
Assembly
CalloraVoipSdk.Client.dll

A signalling-neutral WebRTC peer connection: the app owns the signalling channel (WebSocket/HTTP/ Callora) and exchanges SDP through it, while this peer runs ICE, DTLS-SRTP, BUNDLE and the RTP/RTCP transport. Encoded media flows through SendAudioAsync(ReadOnlyMemory<byte>, CancellationToken)/SendVideoFrameAsync(ReadOnlyMemory<byte>, uint, CancellationToken) — the SDK is transport-only, so the app owns the codec. The central per-connection abstraction of the WebRTC facade, mirroring the SIP ICall.

Written to be consumed, not implemented: it gains members as the facade grows (ADR-006 §2 treats that as additive), so a test double implementing it should expect to add one per minor release.

AddAudioTrack()

Adds an audio track (its own m=audio line on the shared BUNDLE transport, beyond the primary audio anchor) before the first offer, returning a handle to send payloads on it. The happy path: var extra = peer.AddAudioTrack(); await extra.SendFrameAsync(payload, ts);. The SFU pattern of one audio stream per remote participant on a single peer connection.

IAudioTrack AddAudioTrack()

Returns

IAudioTrack

A handle to send encoded audio payloads on the new track.

Remarks

The peer's implicit primary audio track stays the always-on transport anchor; AddAudioTrack adds a further audio m-line. The frameless SendAudioAsync(ReadOnlyMemory<byte>, CancellationToken) keeps addressing the primary track, and DTMF (SendDtmfAsync(byte, int, CancellationToken), RFC 4733) stays on that primary track. A track added before CreateOffer() is negotiated in the first offer; a track added mid-call is pending until the next offer/answer cycle applies it to the running session (RFC 8829 renegotiation). Throws only after the peer is closed.

Exceptions

InvalidOperationException

The peer is closed.

CreateIceRestartOfferAsync(CancellationToken)

Produces an offer that asks the far side to restart ICE (RFC 8445 §9) — the equivalent of the browser's createOffer({ iceRestart: true }). Use it when connectivity has degraded or the local network changed: connectivity checks run again over the same transport, so the DTLS session and the media keys survive and the call is not rebuilt.

This peer's ICE credentials are rotated and its agent restarted before the offer is produced, so the returned SDP announces a restart already in effect here — signal it to the far side as usual. Before the first SetRemoteDescriptionAsync(string, CancellationToken) it behaves exactly like CreateOffer().

GatherCandidatesAsync(CancellationToken)

Gathers server-reflexive ICE candidates (RFC 8445 §5.1.1) from the configured STUN servers, each surfaced on LocalIceCandidateDiscovered to trickle out (RFC 8838). No-op when no STUN servers are configured. Call after producing the offer/answer and before StartAsync(CancellationToken) (the query shares the media socket the transport takes over once started; calling it after StartAsync(CancellationToken) throws). On loopback (the STUN server on the same host) the reflexive address equals the host candidate; redundant-candidate pruning (RFC 8445 §5.4) is a later slice.

RequestVideoKeyFrameAsync(string, CancellationToken)

Asks the peer to send a fresh video key frame on the track identified by mid (RFC 4585 §6.3.1 PLI) — the multi-track overload of RequestVideoKeyFrameAsync(CancellationToken). Use it when the bundle carries several video tracks and only one needs an intra frame (a renderer attach or a decoder reset on that track). Tolerant by design — a no-op returning false when no BUNDLE session is negotiated yet, no track carries that MID, the peer did not advertise PLI (a=rtcp-fb … nack pli), or the built-in throttle still holds; returns true when a PLI was sent. Safe to call from any thread and after disposal (a no-op).

SendDtmfAsync(byte, int, CancellationToken)

Sends one out-of-band DTMF tone (RFC 4733 telephone-event) on the peer's audio track. A no-op is not possible: telephone-event must have been negotiated, otherwise this throws. RecommendedBitrateChanged

Raised whenever the SDK revises its recommended send bitrate to this peer (transport-cc), carrying the finished BitrateRecommendation (bitrate + coarse quality). This is the reactive signal an SFU reacts to per receiver, re-choosing the simulcast layer it forwards when the path's bandwidth changes. Reactive per feedback report (roughly once per round-trip); the SDK does not throttle it — the app decides when and how to act on a change. Remarks

Use this instead of VideoKeyFrameRequested whenever the peer sends more than one video stream, and always in a forwarding server: without the attribution the only safe response to a request is a key frame from every source, which turns one participant's decoder reset into a bandwidth spike from all of them.
