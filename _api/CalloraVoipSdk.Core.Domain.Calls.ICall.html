A single call and its lifecycle.

public interface ICall

Remarks

Event threading contract. Event handlers run synchronously on the SDK thread that raised the event — this is usually not the thread that created the call. Handlers therefore must not block or perform long-running/synchronous I/O: a blocked handler stalls the SDK path that raised it (SIP signaling or media), delaying every other call on the same line. Off-load real work to your own task or queue, e.g. call.StateChanged += (_, e) => _ = Task.Run(() => Handle(e));. Handlers should also not throw. See each event for the specific thread and whether it is serialized.

TransferRequested is the exception to off-loading: it needs a synchronous accept/reject decision, so make that decision quickly inline (do not await long work).

Error contract. The action methods split into two error styles by return type. The core lifecycle operations return Task (or Task<TResult> of bool for AttendedTransferAsync(ICall, CancellationToken)) and throw: invalid usage surfaces as InvalidOperationException (wrong state or direction), ArgumentException (invalid argument), and cancellation surfaces as OperationCanceledException; transport, timeout and unexpected transport-layer failures propagate as-is. The extended in-dialog / inbound-response operations return CallActionResult instead and do not throw for foreseeable outcomes: an invalid state or direction, a protocol rejection (for example a SIP 4xx from the peer), an invalid request, cancellation, and transport failures are all reported as a non-success CallActionResult whose Status classifies the cause (see CallActionStatus). These result-returning methods are the ones that involve a SIP round-trip whose negative answer is a normal protocol result rather than a programming error. Per-method tags below state the exact exceptions and result semantics.

Remarks

Read from whichever header the carrier sent: History-Info (RFC 4244) or Diversion (RFC 5806). The two are ordered opposite ways and no carrier sends both consistently, so a consumer reading one of them directly is correct with part of the market and silently blind with the rest — and blind here means a forwarded call is indistinguishable from a direct one. Both are normalised to this one order.

An empty list means nothing was reported, not that the call arrived directly. A carrier that sends neither header leaves the distinction unavailable.

Diversion stays what it always was — the first URI of the first Diversion header row — for consumers that want exactly that.

MuteAsync(bool, CancellationToken)

Mutes or unmutes this call's outgoing audio locally: the SDK stops (or resumes) sending this call's captured audio to the peer. Unlike HoldAsync(CancellationToken) it is not signalled to the peer (no re-INVITE), and unlike the client-wide device mute (IVoipClient.SetAudioInputMuted) it affects only this call, so on a client with several concurrent calls each mutes independently. While muted the peer receives no audio for this call (no packets are sent for the outgoing direction); inbound audio is unaffected. Local-only, so it is valid in any live state and does not throw for state; a no-op if already in the requested state. Read the current state via IsMuted. The default implementation is a no-op.

RestartIceAsync(CancellationToken)

Initiates a local ICE restart (RFC 8445 §9) on a connected, ICE-negotiated call: the SDK re-gathers on the existing media socket with fresh ICE credentials — a new ice-ufrag and ice-pwd — and re-offers them in a direction-preserving re-INVITE. The ICE role is preserved and media keeps flowing on the previously validated candidate pair until the new connectivity checks nominate a pair. Use this to recover a media path after a network change or a consent loss surfaced by IceConnectionStateChanged.

Events

DtmfReceived

Raised when a DTMF tone is received. This event may fire from two threads: the SIP signaling thread (SIP INFO tones) and the media receive thread (RFC 4733 in-band RTP events). It is therefore not guaranteed single-threaded — keep the handler thread-safe and fast.

HoldStateChanged

Raised when the remote party puts the call on or off hold, and only when the hold state actually changes (a duplicate or pre-Connected hold indication does not re-raise it). Serialized on the SIP signaling thread. Like StateChanged, changes are not buffered for handlers attached later.

IceConnectionStateChanged

Raised when the running ICE transport state changes after establishment (for example Connected → Disconnected on consent loss). Fires on a media/RTCP thread, not the signaling thread. Lets the application react to a lost media path — tear down, alert the user, or (later) trigger an ICE restart. Not buffered.

event EventHandler<CallIceConnectionStateChangedEventArgs>? IceConnectionStateChanged

Event Type

EventHandler<CallIceConnectionStateChangedEventArgs>

MediaFlowChanged

Raised when inbound media goes silent on a connected call, and again when it resumes (#261, ADR-069). Fires on a media/RTCP thread, not the signaling thread. Not buffered.

event EventHandler<CallMediaFlowChangedEventArgs>? MediaFlowChanged

Event Type

EventHandler<CallMediaFlowChangedEventArgs>

Remarks

This is a notification, not a teardown: it fires while the peer is still demonstrably alive (RTCP keeps arriving), which is the normal state during silence suppression (RFC 3389), hold, and the bridge switch of a transfer. The application decides what silence means for its use case — play a prompt, escalate, end the call — long before the SDK's own liveness timeout would. A peer that stops sending everything is a separate matter and ends the call with a CallTerminationReason that says so.

QualitySnapshotChanged

Raised periodically with an updated call-quality snapshot. Fires on a media/RTCP thread (RTCP send-timer and receive driven, not the signaling thread), so it may interleave with the signaling-thread events above. Not buffered.

event EventHandler<CallQualitySnapshotChangedEventArgs>? QualitySnapshotChanged

Event Type

EventHandler<CallQualitySnapshotChangedEventArgs>

StateChanged

Raised when State changes. Serialized on the SIP signaling thread. Changes are not buffered: a handler attached after a transition does not receive that earlier transition. Read State for the current value, and subscribe before initiating an action to observe every subsequent change. See the interface remarks for the handler contract.

TransferRequested

Raised when the peer requests a transfer (SIP REFER), on the SIP signaling thread. The handler must set the accept/reject decision on the event args synchronously (see remarks); it drives the SIP response, so decide quickly and do not await long-running work.
